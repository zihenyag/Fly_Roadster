# FLY! Roadster

桌面浏览器中的第一人称无尽驾驶游戏。Three.js 渲染驾驶舱、完整车身和三面实时镜面，Rapier 负责刚体、连续碰撞和悬挂探测。无音乐；车辆音效与中文导航语音可以分别关闭。

## 本地运行

```sh
npm install
npm run dev -- --port 5173
```

打开终端打印的本地地址。鼠标点击开始、继续、设置或重开。

| 操作 | 左手方案 | 右手方案 |
| --- | --- | --- |
| 油门／刹车 | W／S | ↑／↓ |
| 左／右转向 | A／D | ←／→ |
| 起飞 | 空格 | 右 Ctrl |
| 抓地 | 左 Shift | 右 Shift |
| 暂停 | E 或 Esc；其他非功能键也会暂停 | 同左 |

两套按键始终可用，可以混用；同功能多键不叠加，反向转向抵消，油门刹车同时按下以刹车为主。方向与踏板有平滑响应，高速转向自动收敛。

起飞与抓地使用固定推力，按下即输出，松开即停止，没有轻重档或长按加重。两种推进可以同时使用、分别耗油；空中油门和刹车无效。姿态翻倒时辅助自动开启，只翻正，不自动导航。暂停、失焦会清空输入和推进状态，继续驾驶仍需鼠标点击。

方向盘采用开口平底造型和橙色定位标，地面与空中均随转向旋转；驾驶屏同时显示转角和推进工作状态。驾驶屏、中屏使用独立圆角网格，与各自外壳共同倾斜。外后视镜位于车门外侧，并有独立碰撞体。

推进燃料上限100，每游戏秒恢复6；起飞每秒消耗25，抓地每秒15，辅助工作时每秒5。耗尽后需积累少量燃料才能重新输出，暂停不回充。

## 道路与交通

- 车道宽4.6米，Roadster车身宽约2米；后视镜有独立碰撞体。
- 每局随机种子，至少提前4 km规划道路。前300 m只有正常道路和车流。
- 首个半圆环入口固定在2 km，开局即给出完整2 km预告；后续岔路、半圆环和必须跨越的护栏仍提前2 km提示，不播报危险车辆。
- 只有导航授权时才能跨越护栏。半圆环必须经过倒挂顶端，再飞到侧面接续道路。接续高架与旧路分层，避免返回路线互相穿越。
- 普通交通包括小客车、两厢车、面包车、小货车、大货车和半挂牵引车，会跟车、打灯超车；事故后留下动态刚体障碍。
- V800从后方接近，投放时比玩家快14–20 km/h，后续始终不超过玩家当前车速＋20 km/h；玩家减速时也遵守该上限。
- SU7出现后先短暂保持相邻车道，约0.35秒开始切入，并在出现2秒后进入失控。投放后的轨迹固定，不随玩家车速临时改变。
- 险车从360 m后开始安排，两种车型交替；初期候选间隔220–340 m，3–10 km为180–280 m，之后150–220 m。实际投放保留车流与特技路段的安全检查，不合适时在220 m窗口内重试；10 km前限制为一个正在接近的险车事件。
- 险车投放检查视线遮挡，并在独立物理快照中延迟3.2秒后才开始回放避险操作；不通过则不投放，不会在进入画面后挪车救场。内后视镜缩小广角以放大后车，没有新增车辆警报。
- 车辆、护栏等物体的任何擦碰，以及重摔、走错路线或未经授权抄近路都会结束旅程。允许车身基本朝正、下降速度低于6 m/s、底盘穿入不超过10 cm的轻微擦底，连续托底超过0.3秒或车身重撞路面仍会失败。正常轮胎接地不算事故。

## 画面与性能

- 道路有45 cm厚的实体底面、侧边和端面；飞跃缺口仍然保留，从下方和倒挂环面观察都不会透空。
- 岩石、树木按种子和路段固定生成，整块岩石的旋转包围范围会避让所有已规划道路、岔路两侧与飞跃通道；不会随相机升高重新布景。
- 外后视镜固定在侧窗前角、A柱下端的外侧，短支座收在镜壳下方，镜面避开柱子与门板遮挡；反射视角向外偏，保留内缘少量车身。内后视镜抬到原横杠高度，横杠、A柱和外壳顶部同步升高。外壳、反射相机和碰撞体对齐。镜子分帧轮流刷新，高画质目标30 FPS，低画质15 FPS并降低镜面分辨率。
- 默认自动画质根据持续帧时间调整画面分辨率和镜面刷新率；高、低画质可手动选择。画质不改变道路、车流、石头位置或物理步长。
- 车流按车型共享模型并实例化绘制，每个相机分别剔除视野外车辆；路边物体实例化，静态驾驶舱合批。暂停与准备界面静止时停止重复绘制。
- 物理、车流与完整的避险回放在 Web Worker 中执行，固定120 Hz步长；主线程只接收状态并绘图。画面使用60 ms状态缓冲平滑线程消息，三面镜子与主视角共用同一插值姿态。暂停时后台物理和回充一起停止。
- 本机固定种子、1440×900、DPR 1的渲染对比记录见 `artifacts/render-performance.json`；这是同机测试，不代表所有设备的帧率。

## 验证

自动驾驶：[https://zihenyag.github.io/Fly_Roadster/auto](https://zihenyag.github.io/Fly_Roadster/auto)。直接访问该路由会在标准游戏界面开始自动驾驶，保留完整车流、燃料与失败判定，实时连续行驶，超过10 km后继续跑；失败后等待2.5秒开启新旅程。暂停按钮或非功能键仍会暂停，自动模式允许窗口失焦后继续跑。普通游戏页面没有自动驾驶入口，仍为手动驾驶。

本地可打开 `http://127.0.0.1:5173/auto?seed=0`；固定种子参数只在开发模式生效。构建会生成独立的 `auto/index.html`，GitHub Pages直接访问及刷新此路由都可用。

`npm run play -- 0 12000` 使用同一物理和自动驾驶脚本，从起点带完整车流跑至12 km，逐物理帧记录输入与车况到 `output/autoplay/`，并保留失败原因与路况事件。

```sh
npm test
npm run verify
npm run build
```

`npm test` 覆盖输入、燃料、随机生成、自动辅助、环面约束、车道转向、空中方向盘、车辆事故及险车避险回放，并检查飞跃落地与轻微擦底可通过、无缓冲重落地会失败。

`npm run verify` 检查1,000个种子各30 km的生成约束；使用与游戏相同的物理引擎、真实按键和固定推进输入，回放50个种子各20 km。长距离回放不包含随机交通，交通接触与险车准入另行测试；结果写入 `artifacts/verification.json`。这组检查不是对任意玩家状态或所有无限随机组合的数学证明。

车型使用程序化原创近似模型，并非厂商CAD。桌面宽屏是首版支持的平台；浏览器不提供中文语音时仍保留文字导航。构建产物在 `dist/`，可以静态托管。

## GitHub Pages

项目完全在浏览器运行，不需要后端，不保存历史纪录或游戏存档。资源使用相对路径，可部署在 GitHub Pages 的仓库子目录。

仓库为 `zihenyag/Fly_Roadster`。推送到 `main` 后，`.github/workflows/pages.yml` 会运行测试、构建并发布 `dist/`。也可在 Actions 中手动运行部署。首次部署前，在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**，然后运行工作流。

预期访问地址为 `https://zihenyag.github.io/Fly_Roadster/`；实际部署状态以 GitHub Actions 的部署结果为准。仅上传 TypeScript 源文件或双击打开 `index.html` 不能替代构建与静态托管。
